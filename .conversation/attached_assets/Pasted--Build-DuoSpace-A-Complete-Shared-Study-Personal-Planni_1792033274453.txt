# Build DuoSpace — A Complete Shared Study & Personal Planning Web App

Act as a senior full-stack developer, UI/UX designer, database architect, and security engineer. Build a fully functional, production-minded web application called **DuoSpace** for two people who want to manage Class 12 studies, daily tasks, personal goals, habits, and their shared schedule in one place.

**Important:** Build a working application, not just a visual prototype. All buttons, forms, calendars, filters, task actions, charts, and settings must work. Store data in a real database and make changes synchronize between both users.

## 1. Technology stack

Use:
- React + TypeScript + Vite.
- Tailwind CSS with shadcn/ui components and Lucide icons.
- Supabase PostgreSQL for persistent data.
- Supabase Realtime for live synchronization.
- Supabase Auth or an equivalent secure server-side session system.
- Server-side functions for protected operations and scheduled in-app reminder processing.
- Vercel or Cloudflare Pages for deployment, with Supabase as the backend.

Choose compatible, currently supported dependencies. Create a clean, maintainable project structure with reusable components, loading states, error handling, form validation, and database migrations.

Never expose service-role keys, database passwords, or other server secrets in client-side code.

## 2. Access and two-profile system

Create a Netflix-inspired entry experience.

1. Show the DuoSpace logo and a dark cinematic background.
2. Ask for one shared workspace password.
3. Validate the password securely on the server.
4. After successful validation, show two large profile cards.
5. The user can select either profile without entering another password.
6. Both profiles can view and edit shared tasks, calendar events, academic progress, goals, journals, and other workspace data.
7. Display the currently selected profile and allow switching profiles without signing in again.
8. Include secure logout, session expiry, and session revocation.

Allow the two profile names, avatars, and accent colors to be customized in Settings.

The profiles are for convenience, not separate security boundaries. Both authorized users have shared workspace access. Never store the shared password in plain text or validate it only in the frontend. Rate-limit password attempts and use secure server-side sessions. Do not put the workspace password in URLs, logs, or client storage.

If a single shared password creates limitations in the selected authentication provider, implement a secure server-side workspace access flow and clearly document its setup.

## 13. Website-only reminders and notification centre

**Important: All reminders must appear only inside the DuoSpace website/app. Do not implement email, SMS, browser push notifications, or operating-system notifications.**

Create an in-app notification centre accessible through a bell icon with an unread count.

Generate reminders for:
- Tasks approaching their deadlines.
- Tasks due today.
- Tasks that have become overdue.
- Upcoming exams.
- Scheduled revision sessions.
- Homework and assignment deadlines.
- Habit check-ins, if enabled.
- Shared goal milestones and relevant collaboration updates.

### Default reminder behaviour

Make the default timing configurable. Suggested defaults:
- One day before the deadline.
- Two hours before the deadline.
- A due-now reminder when the task is still incomplete.
- One overdue reminder after the deadline.

Allow users to change reminder timing or turn reminders off for individual tasks.

### Notification rules

- Check the current task status and deadline before creating or displaying a reminder.
- If a task is completed or cancelled, do not show its pending deadline reminders.
- If a deadline changes, update or cancel the old pending reminders.
- Prevent duplicate notifications for the same event.
- Respect the workspace time zone and user-configured quiet hours.
- Allow snoozing, dismissing, and marking notifications as read.
- Allow quick actions such as Complete Task, View Task, Snooze, and Reschedule.
- Shared task reminders should follow the workspace's notification preferences and show which task they concern.
- Clearly distinguish upcoming, due-today, overdue, and informational notifications.

### Implementation requirements

Persist notifications and their delivery/processing state in the database. Process due reminders using a reliable server-side scheduled function or scheduler. Do not rely solely on browser timers, because the page might be closed when a reminder becomes due.

When a user opens the website, fetch and display all currently relevant unread notifications. Recheck task status before presenting a deadline reminder.

Use idempotent reminder processing so repeated scheduled runs cannot create duplicate reminders. Handle retries and failures safely.

The app does not need to send anything outside the website. If both users are online, update their notification centres using Supabase Realtime. If a user is offline, store the notification so it appears the next time they open the app.

Add a notification history page with filters for unread, read, upcoming, overdue, exams, revision, and shared activity.

## 17. Security and privacy

Implement real server-side authorization.

- Enable Supabase Row Level Security on every exposed table.
- Scope all queries and mutations to the authorized workspace.
- Verify membership on the server or through correct RLS policies.
- Never trust a workspace ID, profile ID, or selected profile supplied by the browser without authorization checks.
- Validate inputs on both client and server.
- Protect access and password-change endpoints against brute-force attempts.
- Use secure session cookies or the authentication provider's secure session mechanism.
- Keep secrets and privileged database credentials server-side.
- Avoid logging passwords, session tokens, or private journal contents.
- Prevent one workspace from accessing another workspace's records.
- Verify that users cannot bypass permissions by directly calling database APIs.
- Use safe error messages that do not reveal secrets.

Since this app is intended for two trusted users, the shared workspace is the main access boundary. Do not incorrectly present profile selection as private account authentication.

## 18. Performance and reliability

- Use pagination or sensible limits for long activity and notification lists.
- Add loading skeletons and empty states.
- Provide meaningful error messages and retry actions.
- Prevent double submissions.
- Optimistically update the UI only when rollback is handled correctly.
- Handle network loss and reconnect gracefully.
- Ensure Realtime subscriptions are cleaned up correctly.
- Avoid unnecessary database queries.
- Make the interface accessible with keyboard navigation, clear focus states, and appropriate contrast.
